# GAPLY Development Rules

## General Rules
1. **Understand before modifying**: Before writing or modifying ANY code, understand and internalize the complete project context (see PROJECT_CONTEXT.md).
2. **Incremental development**: Do not build the entire application in one response. Implement features in small, verifiable increments.
3. **Inspect existing code**: Always inspect the existing repository, read configuration, and understand what was generated by create-next-app before making changes.
4. **Avoid unnecessary dependencies**: Do not install dependencies that are not strictly required for solving an actual requirement.
5. **No fake AI**: Do not use arbitrary skill scores or fake AI functionality that only produces text without real logic.
6. **No hardcoded roadmaps**: Do not hardcode a static roadmap as the final solution; the roadmap must be generated based on student data and role requirements.
7. **Separation of concerns**:
   - Keep business logic separate from UI.
   - Keep AI logic separate from deterministic calculations.
   - Use strong TypeScript types.
8. **Input validation and error handling**: Validate all inputs and handle errors properly.
9. **Reusable components**: Build reusable UI components.
10. **Scalable database design**: Design the database to be scalable and follow normalization principles.
11. **Demo-friendly**: Keep the product demo-friendly with clear states and flows.
12. **Problem alignment**: Every major feature must connect back to the PS05 problem (AI Skill-Gap & Personalized Learning Agent). If a proposed feature does not help solve the core problem, question whether it is needed.
13. **No over-engineering**: Do not over-engineer before the MVP works.
14. **Architecture changes**: Do not replace working architecture without a concrete reason. Before major implementation decisions, explain the decision briefly.
15. **Iterative testing**: After implementing a phase, run appropriate checks/tests.
16. **Meaningful Git commits**: Keep Git commits meaningful and phase-based.

## Specific Technical Rules
- **Next.js App Router**: Use the App Router structure (app/) for new pages and components.
- **TypeScript**: Use strict TypeScript typing; avoid `any` where possible.
- **Tailwind CSS**: Use Tailwind for styling; follow existing design patterns in the codebase.
- **Database**: Choose a database that fits the project (e.g., PostgreSQL, MongoDB) and use an ORM (e.g., Prisma) for type safety and migrations.
- **State Management**: For client-side state, consider React Context or Zustand; avoid overusing Redux for simple state.
- **AI Integration**: When integrating AI, use tool/function calling to interact with persistent data; do not rely solely on text generation.
- **GitHub Integration**: Use the GitHub API cautiously, respecting rate limits and handling authentication securely.
- **Authentication**: Implement secure authentication (e.g., NextAuth.js) for user profiles.
- **Validation**: Use a validation library (e.g., Zod) for form and API input validation.
- **Testing**: Write unit tests for business logic and integration tests for critical flows.
- **Error Boundaries**: Use React error boundaries for graceful error handling in UI.
- **Loading States**: Implement skeletons or spinners for asynchronous operations.
- **Accessibility**: Follow accessibility guidelines (WCAG) for inclusive design.
- **Responsive Design**: Ensure the application works on mobile, tablet, and desktop.

## Documentation Rules
- Update PROJECT_CONTEXT.md when the project direction changes significantly.
- Update AGENTS.md when development rules change.
- Before beginning work in any future session, read both PROJECT_CONTEXT.md and AGENTS.md.
- Keep inline code comments meaningful and up-to-date.
- Document complex business logic in comments or separate documentation files.

## Git Workflow
- Create feature branches for each phase or feature.
- Write clear, descriptive commit messages.
- End git commit messages with: `Co-Authored-By: Claude Code <noreply@anthropic.com>`
- For pull requests, end the description with: `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
- Merge pull requests only after review and passing checks.

## AI Agent Usage
- When using the Agent tool, specify the appropriate subagent type (e.g., general-purpose, Explore, Plan) for the task.
- For questions about Claude Code or the Claude API, use the claude-code-guide agent.
- Before spawning a new agent, check if there is already a running or recently completed agent of the same type that you can continue via SendMessage.
- Use the Agent tool for independent work that can be run in parallel.

## Artifact Usage
- When creating charts, graphs, or data visualizations, use the `dataviz` skill first.
- For publishing HTML or Markdown as an Artifact, load the `artifact-design` skill before writing.

## Command Usage
- Use `/help` to see available commands.
- Use `/config` to adjust settings like theme or model.
- Use `/skill-doctor` to diagnose skill issues.
- Use `/design-sync` to synchronize with a design system project.
- Use `/workflow` to run multi-agent orchestration only when explicitly opted into.

## Testing Rules
- Write tests for new functionality as you develop.
- Prioritize testing business logic over UI components.
- Use mocking for external services (e.g., AI APIs, GitHub) in unit tests.
- Ensure tests pass before considering a phase complete.

## Performance Rules
- Optimize images and assets.
- Use Next.js built-in optimization (next/image, next/font).
- Lazy-load components when appropriate.
- Monitor bundle size and avoid large dependencies.
- Implement caching where beneficial (e.g., for skill data, role data).

## Security Rules
- Sanitize user inputs to prevent XSS and injection attacks.
- Use environment variables for secrets; never commit them to the repository.
- Implement proper authentication and authorization.
- Follow Next.js security best practices.
- Regularly update dependencies to patch vulnerabilities.
